📦 ctx.vanshul.com

A public Model Context Protocol server that turns a GitHub repo into agent-ready context — pack it, or search it for just the relevant lines.

https://ctx.vanshul.com/mcp

Tools

pack_repo — fetch a repo and return it as one context blob: files concatenated with clear ==== path ==== headers, binaries/lockfiles/build dirs stripped, with a token estimate. Use include/exclude globs and max_tokens.
search_context — return only the passages matching a query, each with its file path, line number and a relevance score. Token-efficient way to answer "where is X handled?".
list_files — the text files ctx would include (after stripping noise), with byte sizes.
get_file — the full text of a single file by path.

Connect it

Add it to any MCP client that supports remote / Streamable-HTTP servers:

{
  "mcpServers": {
    "ctx": {
      "url": "https://ctx.vanshul.com/mcp"
    }
  }
}

For clients that only speak stdio, bridge with mcp-remote:

npx mcp-remote https://ctx.vanshul.com/mcp

Try it with curl

# Pack a repo (capped to 8000 tokens)
curl -s https://ctx.vanshul.com/mcp -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"name":"pack_repo",
                 "arguments":{"repo":"sindresorhus/slugify","max_tokens":8000}}}'

# Search a repo for just the relevant passages
curl -s https://ctx.vanshul.com/mcp -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call",
       "params":{"name":"search_context",
                 "arguments":{"repo":"sindresorhus/slugify","query":"replace separator"}}}'

Use cases

  • Give an agent a whole codebase — let Claude, Cursor or Continue load a repo as context in one call instead of you pasting 40 files.
  • Answer a question about a repo cheaply — search_context returns the relevant files/lines, not 200k tokens.
  • Focus with globs — include: ["src/**"] / exclude: ["**/test/**"] to pack exactly what matters.
  • Fit a budget — max_tokens caps the blob so it drops cleanly into a context window.

FAQ

What is ctx?
A free, public MCP server that turns a GitHub repo into agent-ready context — pack it into one token-counted blob, or search it for just the relevant passages.

How is it different from gitingest / repomix?
Those pack a repo for humans. ctx is agent-first (an MCP server agents call directly) and adds ranked search_context so an agent gets only the relevant files/lines — a fraction of the tokens.

Which clients can use it?
Any remote / Streamable-HTTP MCP client — Claude Desktop, Cursor, Continue. Point it at https://ctx.vanshul.com/mcp, or bridge stdio-only clients with npx mcp-remote.

Does it need a key or store my code?
No key for public repos, and nothing is stored. It strips binaries, lockfiles and build dirs and returns text deterministically — no LLM in the loop.

What tools does it expose?
pack_repo, search_context, list_files and get_file.
